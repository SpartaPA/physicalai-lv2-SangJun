# 파란색 타깃 찾기 — 바로 실행 안내

아주 쉽게 말하면 **카메라가 파란색을 보고 → 프로그램이 화면에서 위치를 계산하고 → 그 결과를 ROS 토픽으로 알려주는 프로젝트**입니다. 처음 실행할 때는 **카메라와 색 찾기까지만 켜집니다. 모터는 자동으로 켜지지 않습니다.**

실행 기준은 프로젝트 폴더인 `lv2_module5/`입니다. 실행 환경은 프로젝트 문서 기준으로 **RealSense D435가 USB 3으로 연결된 Raspberry Pi**입니다.

## 1. 첫 실행: 카메라 영상에서 타깃 찾기

ROS 2 Lyrical이 설치된 Pi에서, 먼저 한 번만 빌드합니다. 새 터미널을 열 때마다 ROS와 빌드 결과를 `source`해야 합니다.

```bash
cd /home/pa31/GIT/lv2_module3_Sanghwa/lv2_module5/ros2_ws

source /opt/ros/lyrical/setup.bash
colcon build --symlink-install --packages-select realsense_tracker_interfaces realsense_tracker
source install/setup.bash
```

RealSense ROS 드라이버가 없다면 프로젝트 안내에 있는 의존성을 설치합니다.

```bash
sudo apt install ros-lyrical-realsense2-camera python3-opencv python3-numpy python3-yaml \
                 python3-colcon-common-extensions
```

D435를 Pi의 USB 3 포트에 연결하고 **터미널 1**에서 카메라와 파란색 찾기를 실행합니다.

```bash
source /opt/ros/lyrical/setup.bash
source /home/pa31/GIT/lv2_module3_Sanghwa/lv2_module5/ros2_ws/install/setup.bash

ros2 launch realsense_tracker tracker.launch.py
```

이 런치는 기본 설정에서 **RealSense 카메라와 인지 노드만** 켭니다. 제어 노드와 OpenCR 노드는 기본으로 꺼져 있으므로, 이 단계에서는 타깃 위치를 읽어도 모터가 움직이지 않습니다.

**터미널 2**를 새로 열고 같은 ROS 환경을 설정한 뒤 결과를 확인합니다.

```bash
source /opt/ros/lyrical/setup.bash
source /home/pa31/GIT/lv2_module3_Sanghwa/lv2_module5/ros2_ws/install/setup.bash

ros2 node list
ros2 topic list
ros2 topic echo /target
```

파란색 타깃이 보이면 `/target`의 `point.x`, `point.y`, `point.z` 값이 나옵니다. 못 찾으면 세 값이 모두 `0`입니다. 처리 속도는 다음 명령으로 확인합니다.

```bash
ros2 topic hz /target
ros2 topic info -v /target
```

화면에 검출 표시를 띄우고 싶다면 `camera_view.launch.py`를 사용할 수 있습니다. RViz와 깊이 화면 도구는 그래픽 화면이 필요합니다. Pi에 화면 없이 접속한 경우에는 아래처럼 GUI를 끄고 위의 `/target` 토픽으로 확인하세요.

```bash
ros2 launch /home/pa31/GIT/lv2_module3_Sanghwa/lv2_module5/tools/camera_view.launch.py \
  rviz:=false depth_view:=false
```

## 2. 파란색은 어떻게 찾나요?

`detector.py`가 영상에서 파란색에 해당하는 부분을 찾고, 그중 **충분히 크면서 가장 큰 부분 하나**를 타깃으로 고릅니다. 기본 HSV 범위와 크기 기준은 `tracker.yaml`에 있습니다.

`/target`은 3D 거리 측정값이 아닙니다. `point.x`와 `point.y`는 화면 가운데에서 얼마나 벗어났는지를 나타내고, `point.z`는 타깃이 화면에서 차지하는 면적 비율입니다. 깊이 카메라 영상도 구독하지만, 기본 설정에서는 거리를 기록하는 데만 쓰며 `/target`의 `z`에는 깊이가 들어가지 않습니다.

## 3. 노드와 런치 파일

| 이름 | 하는 일 |
|---|---|
| `realsense2_camera` | RealSense 공식 드라이버. 컬러·깊이 영상과 카메라 정보를 발행합니다. |
| `perception_node` | 컬러 영상에서 파란색 타깃을 찾아 `/target`을 발행합니다. |
| `control_node` | `/target`을 받아 좌우·상하 회전 명령을 계산합니다. 기본 런치에서는 꺼져 있습니다. |
| `opencr_node` | 제어 명령을 OpenCR로 전달합니다. 기본 런치에서는 꺼져 있습니다. DRY 설정은 실제 시리얼 포트를 열지 않습니다. |

| 런치 파일 | 용도 |
|---|---|
| `tracker.launch.py` | **첫 실행에 사용하세요.** 카메라와 인지 노드를 켭니다. 제어·OpenCR 실행 여부를 인자로 선택합니다. |
| `control_dry.launch.py` | 카메라 없이 모의 타깃과 제어를 시험합니다. 실제 모터 출력은 없습니다. |
| `camera_view.launch.py` | 카메라·인지와 함께 검출 화면/RViz를 띄우는 도구용 런치입니다. |

`tracker.launch.py`에서 쓸 수 있는 주요 옵션은 `start_realsense`(기본 `true`), `start_control`(기본 `false`), `start_opencr`(기본 `false`)입니다. 모터가 움직이는 실제 추적은 첫 실행과 별도의 하드웨어 확인 절차가 필요합니다. **처음 시험할 때 `start_control:=true`나 `start_opencr:=true`를 추가하지 마세요.**

## 4. 토픽과 데이터 타입

카메라 토픽 이름은 `camera.yaml`에 설정돼 있습니다.

| 토픽 | 데이터 타입 | 발행/구독 | 뜻 |
|---|---|---|---|
| `/camera/camera/color/image_raw` | `sensor_msgs/msg/Image` | 카메라 발행, 인지 노드 구독 | 컬러 영상. 설정은 640×480, 30fps입니다. |
| `/camera/camera/aligned_depth_to_color/image_raw` | `sensor_msgs/msg/Image` | 카메라 발행, 인지 노드 구독 | 컬러 영상에 맞춘 깊이 영상. 기본 형식은 `16UC1`이며 값 1은 1mm입니다. |
| `/camera/camera/color/camera_info` | `sensor_msgs/msg/CameraInfo` | 카메라 발행 | 컬러 카메라 정보. 인지 노드는 이 토픽을 구독하지 않습니다. |
| `/target` | `geometry_msgs/msg/PointStamped` | 인지 노드 발행, 제어 노드 구독 | 타깃의 화면 위치와 면적 비율입니다. |
| `/perception/debug_image` | `sensor_msgs/msg/Image` | 인지 노드 발행 | 검출 표시가 그려진 영상. 디버그 설정을 켰을 때만 나옵니다. |
| `/perception/mask` | `sensor_msgs/msg/Image` | 인지 노드 발행 | 파란색으로 판정된 픽셀을 나타냅니다. 디버그 설정을 켰을 때만 나옵니다. |
| `/control/pan_tilt_cmd` | `realsense_tracker_interfaces/msg/PanTiltCommand` | 제어 노드 발행, OpenCR 노드 구독 | 좌우·상하 속도 명령. |
| `/tracking_status` | `std_msgs/msg/String` | 제어 노드 발행 | `IDLE`, `TRACKING`, `LOST` 상태입니다. |
| `/opencr/bridge_status` | `std_msgs/msg/String` | OpenCR 노드 발행 | OpenCR 연결·상태 정보입니다. |
| `/opencr/dry_status` | `std_msgs/msg/String` | DRY 모드 발행 | 실제 모터가 아닌 모의 명령 결과입니다. |

토픽 이름 앞의 `/camera/camera/`처럼 `camera`가 두 번 들어간 표기는 설정된 실제 이름입니다. 카메라 토픽은 `ros2 topic list`로도 확인할 수 있습니다.

## 5. `/target` 값 읽는 법

`/target`의 타입은 `geometry_msgs/msg/PointStamped`입니다. 위치 데이터는 `point` 안에 있고, 촬영 시각과 좌표계 정보는 `header`에 있습니다.

| 필드 | 뜻 |
|---|---|
| `point.x` | 좌우 위치 오차. 오른쪽이면 양수, 왼쪽이면 음수입니다. |
| `point.y` | 위아래 위치 오차. 아래쪽이면 양수, 위쪽이면 음수입니다. |
| `point.z` | 화면에서 타깃이 차지하는 비율. 타깃을 못 찾으면 `0`입니다. |
| `header` | 입력 영상의 시각과 좌표계 정보를 담습니다. |

`/target`은 최신 값 위주로 받도록 **BEST_EFFORT, depth 1** 설정입니다. 제어 노드도 이 설정과 맞춰 구독합니다.

제어 명령 타입인 `PanTiltCommand`는 `PanTiltCommand.msg`에 정의돼 있습니다. `header`, `stop`, `pan_velocity_rad_s`, `tilt_velocity_rad_s`를 담습니다. `stop`이 `true`면 두 축 모두 정지 명령입니다.

## 6. 전체 흐름 한눈에 보기

```text
D435 카메라
    │ 컬러 영상 + 정렬된 깊이 영상
    ▼
realsense2_camera
    │ /camera/camera/color/image_raw
    ▼
perception_node ── 파란색 찾기
    │ /target (PointStamped: x=좌우, y=상하, z=화면 점유 비율)
    ▼
control_node ── 타깃이 가운데 오도록 속도 계산
    │ /control/pan_tilt_cmd (PanTiltCommand: 좌우·상하 속도)
    ▼
opencr_node ── USB 시리얼
    ▼
OpenCR ── DYNAMIXEL 좌우(Pan)·상하(Tilt) 모터
```

위 흐름에서 첫 번째 실행은 **점선 아래 단계 없이**, 카메라부터 `/target` 발행까지만 확인합니다. 실제 모터로 이어지는 단계는 별도 설정과 안전 절차가 있어야 실행됩니다.

## 7. 실행이 안 될 때 확인할 것

- `ros2 launch`가 패키지를 못 찾으면, 그 터미널에서 ROS와 워크스페이스 `setup.bash`를 모두 `source`했는지 확인합니다.
- 카메라 토픽이 없으면 D435 USB 연결과 `realsense2_camera` 설치 상태를 확인합니다.
- `/target` 값이 계속 0이면 파란 타깃이 카메라에 보이는지 확인합니다. 크기나 조명에 따라 기본 HSV 범위에 들지 않을 수 있습니다.
- `/target`이 없으면 `perception_node` 로그와 `ros2 node list`를 확인합니다.

**검증 주의:** 프로젝트 문서는 Raspberry Pi에서 D435와 전체 시스템을 함께 실행한 시험을 아직 `NOT VERIFIED`로 표시합니다. 따라서 위 명령은 코드에 맞춘 실행 절차이며, 실제 Pi에서 D435 연결과 처리 속도는 현장에서 확인해야 합니다.

아래 명령은 **매번 새 터미널에서** 실행합니다. 마지막 `source`는 빌드 후 설치된 패키지를 찾게 해줍니다.

```bash
source /opt/ros/lyrical/setup.bash
source /home/pa31/GIT/lv2_module3_Sanghwa/lv2_module5/ros2_ws/install/setup.bash

export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST

ros2 launch /home/pa31/GIT/lv2_module3_Sanghwa/lv2_module5/tools/camera_view.launch.py
```

RViz 창에 **원본 컬러 영상, 파란색 검출 결과, 색상 마스크, 정렬된 깊이 영상**이 표시됩니다. 파란색 타깃을 카메라 앞에 두면 검출 결과를 확인할 수 있습니다.

> 위 명령은 `lyrical` 환경 기준입니다. 다른 ROS 2 배포판을 사용한다면 `/opt/ros/lyrical/setup.bash` 경로를 해당 배포판의 경로로 바꾸세요. `realsense2_camera` 드라이버도 PC에 설치돼 있어야 합니다.

## 3. 토픽을 터미널에서 보기

런치를 실행해 둔 채 **두 번째 터미널**을 열고, 같은 환경을 설정합니다.

```bash
source /opt/ros/lyrical/setup.bash
source /home/pa31/GIT/lv2_module3_Sanghwa/lv2_module5/ros2_ws/install/setup.bash
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
```

카메라·인지 노드가 보이는지 확인:

```bash
ros2 node list
ros2 topic list
```

파란색 타깃의 위치와 면적 비율을 실시간으로 보기:

```bash
ros2 topic echo /target
```

- 파란색을 찾으면 `point.x`, `point.y`, `point.z`가 출력됩니다.
- 못 찾으면 `point.x`, `point.y`, `point.z`가 모두 `0`입니다.
- `x`는 좌우 오차, `y`는 위아래 오차, `z`는 화면에서 파란색 타깃PC에 D435를 직접 연결해 시험할 때는 **RealSense 카메라 드라이버 + 인지 노드 + RViz2**를 실행하면 됩니다. OpenCR이나 라즈베리 파이는 필요하지 않습니다.

## 토픽을 터미널에서도 확인하기
